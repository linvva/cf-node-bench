# 使用指南

[返回项目首页](../README.md)

## 下载与运行

从 [Releases](https://github.com/linvva/cf-node-bench/releases) 选择适合系统和 CPU 架构的文件。文件名统一以 `CF-Node-Bench-<tag>-` 开头，`<tag>` 是版本标签；以下表格列出后缀。

| 系统 | CPU 架构 | 文件后缀 |
| --- | --- | --- |
| Windows | Intel / AMD 64 位 | `windows-amd64.exe` |
| Windows | ARM64 | `windows-arm64.exe` |
| Linux | Intel / AMD 64 位 | `linux-amd64` |
| Linux | ARM64 | `linux-arm64` |
| macOS | Intel | `macos-amd64.zip` |
| macOS | Apple Silicon（M 系列） | `macos-arm64.zip` |

Windows 文件无需解压，双击运行；需要 WebView2 Runtime。macOS 文件解压后打开 `CF-Node-Bench.app`，需要 macOS 12 或更高版本；如系统提示应用未签名，可在 Finder 中右键选择“打开”。

Linux 文件没有扩展名，需要 GTK4 与 WebKitGTK 6.0 桌面运行库。首次运行时在下载目录添加执行权限，再启动应用。将下面的 `<tag>` 替换为实际版本标签；ARM64 设备将 `amd64` 改为 `arm64`：

```bash
chmod +x './CF-Node-Bench-<tag>-linux-amd64'
'./CF-Node-Bench-<tag>-linux-amd64'
```

Release 共提供 6 个应用文件，以及 `update-manifest.json` 和 `SHA256SUMS.txt`。后者可用于核对下载文件的 SHA-256。许可证可在应用“设置”中离线查看。

在“设置 → 应用更新”或侧栏版本入口检查新版本。点击“下载更新”，等待校验完成后选择“重启并更新”；测速或发布任务结束后才能重启。更新需要程序所在目录可写。不含自更新功能的旧版需要先手动下载，手动安装与应用内更新使用同一文件。

## 添加节点

可在“数据源”中启用或添加 HTTP 地址，也可在工作台选择本地文件、将文件拖入桌面应用。

支持 CSV、TXT 和 JSON。常见文本格式如下；未提供端口时使用 443：

```text
104.18.1.20:443#US
104.18.1.21:8443
104.18.1.22
```

JSON 支持 `ip` / `host`、`port` 和 `country` / `cc` 字段。CSV 可使用 `IP地址` / `ip` / `host` / `address`、`端口号` / `port`、`IP位置` / `country` / `cc` 表头。文件须为 UTF-8，可带 BOM；导入时忽略旧测速成绩和出站 IP。文件解析失败或没有有效节点时不会启动测速。

本地文件测速只使用本批文件候选，并额外带入当前模式的固化节点，不混入 HTTP 数据源或上轮保留节点。文件路径不会保存为数据源；如需测试修改后的文件，请重新选择。

## 选择测速模式

| 模式 | 测速流程 | 支持的候选 |
| --- | --- | --- |
| 普通 | TCP → HTTPS → 下载 → 排名 | IPv4 地址与端口 |
| H3 | DNS → QUIC → HTTP/3 → H3 下载 → 排名 | IPv4 地址与端口、域名入口 |

两种模式共用测速参数和发布凭据，分别保存固化节点及发布目标。测速运行中不能切换模式，参数以启动时的设置为准。

### 普通模式

通过候选地址建立连接，以 `speed.cloudflare.com` 作为 HTTPS 验证目标并正常验证证书。连接成功率、HTTP 成功率和有效带宽是排名门槛，未达标节点不会仅凭某项高分进入结果。

### H3 模式

默认使用公共验证目标，也可在“H3 高级设置”填写自己的域名，不含协议、端口或路径。H3 验证不需要 UUID、密码或订阅地址；需要检查自己的部署时，应使用自己的验证域名。

H3 强制使用 QUIC 与 HTTP/3，不回退到 TCP 或其他 HTTP 协议。域名会解析为本轮固定的 IPv4 快照；同一实际地址与端口共享测量。普通节点只有全部解析 IP 通过各项门槛才能进入结果，聚合采用较差成绩。结果保留原域名，详情中可查看逐 IP 指标。

验证结果仅说明本轮入口能够访问指定目标，不代表完整 XHTTP、ECH 或 ProxyIP 出站已经验证。导入客户端后仍需验证实际使用的完整链路。

## 测速与保留规则

### 过滤、补测与排名

端口或允许国家为空时表示不限；排除国家优先于允许国家。连接与 HTTP 探测在剩余采样已不可能达标时提前淘汰，通过节点仍完成所需采样。

HTTP 阶段检测全部连接合格的新节点，再按成功率和延迟排序进入下载队列。“HTTP 候选批量”控制首批及后续每次补入的数量，不是总测试上限。带宽通过数未达目标时，会继续从剩余 HTTP 合格候选中补入，直到达到目标、候选耗尽或用户取消。

达到目标后停止启动新任务，并等待在测任务完成，因此通过数可能略超目标。最终结果按“最终结果数”选优；固化与上轮保留复测会增加实际测量量。评分综合考虑带宽、HTTP 请求、连接、可用性和抖动，权重可在设置中调整。

### 下载测速地址

在设置中选择内置测速地址，或填写自己的 HTTPS 地址。地址需要能通过待测 Cloudflare 节点访问，并直接返回足够大的内容；连接使用候选地址，TLS 与 HTTP 的目标、路径及查询参数来自测速 URL。H3 模式的地址必须支持 HTTP/3。

最大下载量与测量时限可在设置中调整。达到测量时限且已收到足够数据时，按实际字节数和耗时计算带宽；用户取消、异常断流或数据不足时计为失败。第三方测速地址的可用性和限速情况可能变化，需要稳定测量时可使用自己控制的地址。

### 上轮结果复检

启用“全量测速时优先复检上轮结果”后，常规测速会优先处理最近一次相同协议、验证目标一致的已完成结果。普通模式复用上轮 TCP 指标，执行 HTTPS 复检和带宽测速；H3 模式完整复检。

上轮保留节点不占新节点的带宽通过目标，复检失败时会被淘汰。取消的运行不会替代最近一次已完成结果。

### 固化节点

在结果表中点击节点地址旁的图钉可固化或取消固化，点亮表示已固化。配置按普通 / H3 模式分别保存，重启应用后仍有效。

固化节点即使不再出现在数据源中，也会额外带入测速。它们绕过国家、端口和测速通过门槛，更新测量信息后加入最终列表，不占新节点候选池、带宽通过目标或最终结果名额。未达标时显示“固化保留 · 未通过”，不显示有效评分；复制、导出和发布仍包含该节点。测速中不能更改固化配置。

### 取消测速

没有完整通过节点时直接取消；已有完整通过节点时，可以选择保留并结束、丢弃本轮结果或继续测速。选择期间任务继续运行。

保留结果只使用已完整完成连接、HTTP 和带宽测速的节点，并按现有排名和数量上限整理；已完整测完的固化节点额外保留。H3 域名必须完成全部解析 IP 的测量，正在采样的节点不会保留。

保留后标记为“已取消，已保留部分结果”，支持查看、复制、导出和手动发布，不会自动发布。

### 阶段重测

“开始测速”右侧菜单可选择从连接、HTTP、带宽或排序阶段继续。重测会复用此前已完整结束的阶段；仅重新排序不发起网络请求。

检查点过期、网络或相关设置变化时会提示确认。若缺少必需测量，或放宽门槛后需要重新采样，应从更早阶段或全量测速开始。H3 从 QUIC 重测会刷新 DNS，后续阶段沿用已有快照；改变验证域名后必须重新测量 QUIC。

只保留工作台当前结果对应的检查点。取消时即使保留了部分结果，未完成阶段也不能作为完整检查点复用。

## 发布结果

在“发布”页配置渠道并保存。成功完成测速后自动发布，也可在结果表中手动发布或重试。发布失败不影响测速结果。

普通和 H3 模式分别设置发布目标，共用账号凭据。发布页切换模式仅影响正在编辑的目标，不改变工作台的测速模式。未配置某模式的目标时会跳过对应渠道，不借用另一模式的目标；历史结果始终按其实际测速协议发布。

### 输出格式

Cloudflare TXT、GitHub 仓库文件、Gist 文件和 Telegram 节点列表共用输出设置，支持预设、字段勾选和实时预览。

| 预设 | 示例 |
| --- | --- |
| 极简 | `104.18.1.20:443#US` |
| 简洁 | `104.18.1.20:443#US\|44ms\|186M` |
| 详细 | `104.18.1.20:443#US\|TCP22ms\|HTTP44ms\|186Mbps` |

简洁格式将数值四舍五入为整数，`44ms` 表示 HTTP 请求平均延迟，`186M` 表示 186 Mbps。勾选连接延迟时使用 `TCP` / `QUIC` 前缀区分。详细格式保留指标名称、单位和小数；H3 始终带协议标记，例如 `edge.example.com:443#US|H3|44ms|186M`。

### 渠道配置

| 渠道 | 所需配置与行为 |
| --- | --- |
| Cloudflare DNS | Token、Zone ID、记录名与类型。A 记录仅发布端口为 443 的 IPv4；TXT 可发布包含端口和域名的完整列表 |
| GitHub 仓库 | Token、仓库、分支与文件路径。更新指定文件，内容不变时不创建新提交 |
| GitHub Gist | 独立 Token、已有 Gist ID 与文件名。只更新目标文件，支持复制固定 Raw 地址 |
| Telegram | Bot Token 与 Chat ID。可选择仅发送汇总，或附带节点列表；直连受限时可部署[专属中继](../deploy/telegram-relay/README.md) |

普通与 H3 的目标应分开设置。Gist 可以使用同一 Gist 的不同文件，也可使用不同 Gist；应用不会创建 Gist 或更改其可见性。固定 Raw 地址指向最新内容，更新后可能有缓存。

“测试连接”只检查目标访问能力，不发布结果。Token 应仅授予所需权限：Cloudflare DNS 编辑、GitHub 仓库内容写入、Gist 写入。Secret Gist 仍可由持有链接的人访问。

Cloudflare 类型切换时，只替换带有应用管理标记的同名记录。符合条件的结果为空时不会清空已有记录。

## 本地数据与网络

设置、凭据和历史位于操作系统配置目录的 `CF Node Bench` 文件夹；`data.json` 保存配置与历史，`checkpoint.json.gz` 保存阶段检查点，Windows 的 WebView 数据位于 `WebView2` 子目录。

凭据以明文保存在本机，不返回界面、不写入测速历史或错误日志。发布页中留空表示保留已保存凭据，清除时使用专门的清除按钮。备份或共享配置文件时应保护其中的凭据。

测速和发布由桌面应用从本机直接发起，不通过系统代理。浏览器开发预览使用演示数据，不进行真实测速或外部发布。Telegram 专属中继会经用户自己的 Worker 转发消息，其部署与数据说明见[中继文档](../deploy/telegram-relay/README.md)。
